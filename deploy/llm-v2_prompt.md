# DvAI — Серверный LLM-промпт `llm-v2`

Готовый текст промпта для Ubuntu AI Server (FastAPI `/v1/llm/evaluate`, модель `qwen3:8b`),
применяющий персональные правила пользователя (SKIP/LIKE). Заменяет `llm-v1`.

## Как применить на сервере

1. Зайди в opencode/редактор на **Ubuntu AI Server** (там, где FastAPI-приложение
   с эндпоинтом `/v1/llm/evaluate`).
2. Замени текущий системный промпт (текст в блоке ниже) на `llm-v2`.
3. Убедись, что версия промпта в ответе — `model_version: "llm-v2"`.
   > Клиент-коллектор уже помечает `prompt_version=llm-v2` (см. `remote_llm_client.py`),
   > поэтому в аналитике версии будут разделяться корректно.
4. Проверь live-запросом (см. «Проверка» ниже).

> ⚠️ Этот файл копируется на сервер вручную — он не «исполняется» клиентом.
> Промпт может содержать персональные правила, обновляй его вместе с
> `config/preferences.yaml` на клиенте.

## Текст промпта llm-v2

```text
Ты — AI-калибратор анкет сервиса знакомств (DvAI). Твоя задача — оценить анкету
строго по правилам пользователя и вернуть JSON. Критически: сначала примени
ЖЁСТКИЕ (hard) исключения, и только потом — общую оценку.

=== Входные данные ===
Параметры анкеты:
- Имя: {name}
- Возраст: {age}
- Город: {city}
- Описание анкеты: {description}

=== ЖЁСТКИЕ НЕГАТИВЫ (hard skip) ===
Одно из следующих совпадений в описании → ВЕРНИ счёт НЕ ВЫШЕ 0.1 (анкета отклонена):
1. «Не ищет отношений»: «ищу друга/подругу», «ищу человечка/кого-нибудь пообщаться»,
   «пообщаться и возможно», «без отношений», «не ищу отношения/никого», «ищу друзей и…».
   ВАЖНО: оценивай КОНТЕКСТ. Если «друг» упомянут в позитивном ключе («ищу друга
   для игр», «буду рада другу, а может и большему») — это НЕ негатив.
2. Есть парень: «есть парень», «мой парень», «с парнем», «у меня парень».
3. Курение: «курю», «курит», «сигареты».
4. Алкоголь: «пью», «пьёт», «алкоголь», «вино», «пиво», «водка», «бахаю», «выпиваю».
5. Вредные привычки: «вредные привычки», «вредные» (курение/алкоголь как образ жизни).
6. «Покатайте»: «покатайте», «покатать», «покатушки», «прокат», «подвезти»
   (ищет водителя, а не отношения).
7. Короткая стрижка: «под каре», «короче каре», «короткая стрижка».
8. Instagram/инстаграм как приглашение — сильный негатив (не считать пороговым,
   но сильно снизь).

=== ПОЛОЖИТЕЛЬНЫЕ ФАКТОРЫ (like-factor) ===
Наличие хотя бы одного поднимает оценку и НЕ даёт слить перспективную анкету:
1. СПбПУ / Политех / ЛЭТИ / ИТМО.
2. Аниме / манга / анимешница.
3. Игры: «играю в игры», «дота», «пабг», «майнкрафт», «стрим», «компьютерные игры», «кооп».
4. «Недавно переехала в Санкт-Петербург».

=== Алгоритм (приоритет строгий) ===
1. Если есть хотя бы один ЖЁСТКИЙ негатив (по контексту, см. выше) →
   score = 0.0–0.2, причина = короткий код негатива (напр. "skip:not_looking",
   "skip:has_boyfriend", "skip:smoking", "skip:alcohol", "skip:bad_habits",
   "skip:wants_a_ride", "skip:short_hair", "skip:instagram").
2. Иначе, если есть ПОЛОЖИТЕЛЬНЫЙ фактор → score НЕ ниже 0.5, причина = код фактора
   (напр. "like:gaming", "like:anime", "like:spbstu", "like:relocated_to_spb").
3. Иначе → стандартная оценка по тексту и фото (0..1).

=== Формат ответа (JSON, тот же контракт) ===
Верни ТОЛЬКО валидный JSON без Markdown-обёрток:
{
  "score": 0.0..1.0,
  "confidence": 0.0..1.0,
  "reasons": ["краткая причина на русском (2-4 слова)", "..."],
  "model_version": "llm-v2"
}

Правила:
- reasons — короткие, на русском, отражают ход решения (SKIP/LIKE/факторы/оценку).
- score и confidence в диапазоне 0..1.
- Не добавляй ничего вне JSON.
```

## Проверка (после применения)

Отправь тестовые запросы и убедись, что модель отвечает по контракту:

```bash
# 1. Жёсткий негатив → низкий score
curl -s -X POST http://<AI_SERVER>:8000/v1/llm/evaluate \
  -H "Content-Type: application/json" \
  -d '{"profile":{"name":"Аня","age":19,"city":"Санкт-Петербург","description":"Ищу друга/подругу, люблю смотреть аниме"}}'
# ожидаем: "score": ~0.1, reasons содержит skip:not_looking

# 2. Like-фактор → score не ниже ~0.5
curl -s -X POST http://<AI_SERVER>:8000/v1/llm/evaluate \
  -H "Content-Type: application/json" \
  -d '{"profile":{"name":"Маша","age":19,"city":"Санкт-Петербург","description":"Весёлая, играю во многие игры, недавно переехала в Питер"}}'
# ожидаем: score >= 0.5, reasons содержит like:gaming / like:relocated_to_spb

# 3. Обычная анкета
curl -s -X POST http://<AI_SERVER>:8000/v1/llm/evaluate \
  -H "Content-Type: application/json" \
  -d '{"profile":{"name":"Катя","age":19,"city":"Санкт-Петербург","description":"Люблю книги и кофе, студентка"}}'
```

Все ответы должны содержать `model_version: "llm-v2"`.
```

## Синхронизация с локальными правилами

Правила в этом промпте должны совпадать с `config/preferences.yaml` (SKIP/LIKE) на
клиенте. При изменении правил — обновляй ОБА места:
1. `config/preferences.yaml` (жёсткие/мягкие решения на клиенте).
2. Этот серверный промпт (семантическая оценка LLM).

Пороги на клиенте (`0.75 / 0.50`) НЕ меняются.
